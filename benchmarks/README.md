# Bounded operational decision screens

This directory separates **recorded observations on withheld private prompts** from an **independent public synthetic fixture**. It never substitutes edited prompts for the prompts actually tested.

## Recorded observations

Both models completed one frozen 72-case screen: 24 usage-meter routing cases, 24 evidence-sufficiency cases, and 24 statement-checking cases. Requests were authored around cloud observations and explicit constraints. Gold labels came from metric categories, field presence, arithmetic, and those supplied constraints. They were not generated by another model.

| Correct result | Clef-Flash 9B | Clef 27B |
|---|---:|---:|
| Routing decision | 24/24 | 24/24 |
| Evidence-sufficiency decision | 21/24 | 24/24 |
| Statement-checking decision | 22/24 | 24/24 |
| Decision, all tasks | 67/72 | 72/72 |
| Decision and evidence selection, all tasks | 61/72 | 72/72 |
| Both decisions correct in a paired family | 31/36 | 36/36 |
| Warm HTTP median | 0.159 s | 0.221 s |

Both ran on the same one-GPU NVIDIA RTX PRO 6000 configuration with 20 vCPU and 80 GiB, using one sequential client. **These are not L4 results.** Warm samples exclude the first request after service readiness; first requests also performed additional initialization. HTTP measurements include the client/network path and come from one sequential pass, not a latency SLO. The ledger contains the remaining aggregate timing measurements. Zero output tokens do not imply zero allocated-GPU cost.

Flash missed required CPU/memory observations, rejected one supported configuration and one correct byte conversion, and accepted a claim that current storage bytes establish an exact historical invoice. These failures support treating it as an advisory screen rather than an unattended approval gate. The routing result makes routing a candidate for further testing; it does not establish an advantage over deterministic rules.

The cases form **36 dependent pairs**, reuse evidence, contain explicit rules, and offer only one substantive evidence packet plus two generic distractors. This is an intentionally bounded reading/checking exercise. It does not demonstrate production FinOps savings, SRE incident judgment, vulnerability prioritization, reliable verification of frontier-model outputs, or general superiority of either model. A perfect score here is not a safety guarantee.

`recorded-results.json` contains only neutral case IDs, task/family labels, gold choices, the two models' selected choices, and aggregate measurements. Original prompts, raw responses, infrastructure identifiers, account usage, timestamps, paths, endpoints, credentials, and IAM records are withheld. The choice ledger permits independent verification of aggregate arithmetic; **the original private-prompt experiment cannot be rerun from this repository**.

Recompute the reported counts without network access:

```sh
python3 benchmarks/score.py
python3 -m unittest discover -s benchmarks -p 'test_*.py'
```

## Independent examples for future runs

`make_synthetic.py` creates 72 paired examples with invented quantities and generic facts. The task formats resemble the recorded screen, but these are independently authored examples with different prompts and values. **Neither model's published result applies to this fixture; this fixture has not been run against the models for the recorded comparison.** IDs begin with `demo-` so the scorer rejects accidentally mixing these examples with the observation ledger.

```sh
python3 benchmarks/make_synthetic.py
```

Each case contains an API-ready `payload`, task and family IDs, and `gold` choices. For a future controlled test, send only `payload` to `/v1/systemone`, replacing `payload.model` with the selected model variant. Keep `gold` outside the request. Run models against exactly the same frozen fixture. Model invocations can start billable GPU instances; follow the repository's IAM, scaling, and cost controls. Fixture generation, scoring, and tests make no network calls.

The optional runner uses your separately authenticated `gcloud` CLI and requires
an existing service already paused at MANUAL zero. After finishing any other
work, use `scripts/set_scaling.py 0` with the intended project/service settings
to request that pause; it disables incoming service. Then inspect metadata
without invoking the model:

```sh
PROJECT=example-project REGION=us-central1 SERVICE=clef-flash MODEL=clef-flash \
  python3 benchmarks/run.py --preflight-only
```

An explicitly authorized paid run temporarily changes that existing service from MANUAL zero to one instance, executes this fixture once without inference retries, and attempts to return it to MANUAL zero. It refuses an already running workload, disabled IAM checks, public service-policy bindings, or a maximum above one. Inherited project/folder/organization IAM is not inspected; verify effective invocation access separately. It does not deploy a model or change the hardware shape.

```sh
PROJECT=example-project REGION=us-central1 SERVICE=clef-flash MODEL=clef-flash \
  python3 benchmarks/run.py --allow-paid --max-seconds 600
python3 benchmarks/score.py --dataset benchmarks/synthetic-cases.json \
  --predictions benchmarks/data/results-clef-flash.json
```

The timeout is a best-effort cleanup deadline, **not a hard billing cap**: control-plane operations, initialization, and shutdown take time. Results are private local files under ignored `benchmarks/data/`; inspect cleanup status and actual Cloud Run state after any interrupted run. A second model must be deployed to its own existing service and selected explicitly. This portable runner has been tested offline with mocked lifecycle calls; it has not been exercised against a live service. No additional paid runs were performed to prepare these public artifacts.

For scoring a new run, retain only selected answer choices in this form:

```json
{
  "dataset_sha256": "canonical fixture fingerprint printed by make_synthetic.py",
  "predictions": [
    {"id": "demo-route-01-a", "answers": {"decision": "compute", "evidence": "E1"}}
  ]
}
```

The fingerprint is SHA-256 of UTF-8 `json.dumps(dataset, sort_keys=True, separators=(",", ":"))`. All 72 distinct case IDs and valid choices are required. The scorer refuses incomplete runs and a mismatched fixture rather than reporting them as complete successes.

```sh
python3 benchmarks/score.py --dataset benchmarks/synthetic-cases.json --predictions YOUR_RESULTS.json
```

For real operations, prefer typed measurements and code for accounting, units, required-field checks, and enforced constraints. Evaluate any model's additional value using held-out real questions and human-reviewed labels before allowing it to suppress consequential work.
